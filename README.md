This project designs a database for a DJ's music library. We decided to focus on Artists, Songs, Albums, and Genres with relevant information that could create playlists of songs and organize a lot of data in a streamlined way.

A challenge was how to decide how to treat genres because artists, songs, and albums each can have many genres and sub-genres. For the purpose of this database, we have decided that these (artists, songs, albums) will have a 1:1 relationship with genres and only allow the primary genre to be recorded.

We have already gone through iterations of making this database more and less complicated and will surely go through more as we continue this project. We discussed adding more foreign keys to tables, like including artist_id in the song table; however, they are already related through the album_id. We also discussed adding a playlists table and are likely to do that in the future. The creation of that many:many (playlists:songs) would necessitate the creation of another table linking the two and normalizing the data. For the purpose of this part, we decided to be iterative based on the sample data we had available and will continue to collaborate on improvements.
